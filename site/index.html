Brain. Muse Spark turns a plain request into presses. The plan is checked in code against the live screen read before anything moves, and a plan that doesn’t add up gets refused with a plain reason.

    04

    How it works

    1. Eyes. A webcam watches the panel. SAM 3.1 finds the buttons and the screens; Muse Spark reads what the screens say, voting across reads.
    2. Brain. Muse Spark plans the presses from the live screen read, then the plan is checked in code against that same read before anything moves.
    3. Finger. An ESP32 drives a servo that presses the real button. Two fingers on the rig: H and ST/SP.
    4. Gut check. Muse Spark Open scores each risky step with a tier and a one-line reason. It can only add, never remove an approval.
    5. The call. A human holds approve. Steps that turn something on always need the hold, whatever the score says.

    06

    Safety

    Every rule below lives in the code, not just on this page.

    • The approval gate lives inside the press tool, so the agent can’t skip it. (backend/mcp_server.py)
    • Steps that turn on output always need hold-to-approve, whatever the risk score. The backend refuses a tap. (backend/api.py)
    • The risk scorer can only add a tier and a reason, never remove an approval. If it fails, the step scores high. (risk/scorer.py)
    • Reads are voted: two reads agree, or a third breaks the tie. A low-confidence read pauses the job instead of pressing blind.
    • Press budget: 30 presses per job. Going over is refused, nothing pressed.
    • Plans that don’t add up get refused with a plain reason. (backend/planner.py checks the plan against the screen)
    • A press that didn’t register gets retried, but never on an approval step, where a double-press would undo the job.
    • Buttons with no finger are never planned. STOP is always on screen and lifts the finger right away, even mid-hold.

    09

    Run it yourself

    No hardware needed. This runs the backend on FakeHardware plus the web app. You need your own Meta Model API key and Baseten key in a repo-root .env file (MODEL_API_KEY and BASETEN_API_KEY).

    Mac / Linux

    python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
FAKE_CONFIDENCE=high FAKE_LOW_READ=2 FAKE_MISS_PRESS=btn_h .venv/bin/python backend/api.py

    Then the web app, in another terminal:

    cd web
npm install
NEXT_PUBLIC_USE_MOCK=false NEXT_PUBLIC_BACKEND_URL=http://localhost:8000 NEXT_PUBLIC_DEVICE_ID=timer-01 npm run dev

    Windows Command Prompt

    python -m venv .venv
.venv\Scripts\python -m pip install -r backend\requirements.txt
set FAKE_CONFIDENCE=high
set FAKE_LOW_READ=2
set FAKE_MISS_PRESS=btn_h
.venv\Scripts\python backend\api.py

    Then the web app, in another terminal:

    cd web
npm install
set NEXT_PUBLIC_USE_MOCK=false
set NEXT_PUBLIC_BACKEND_URL=http://localhost:8000
set NEXT_PUBLIC_DEVICE_ID=timer-01
npm run dev

    Open http://localhost:3000. The fake flags replay the low read and the missed press from the timer replay above. Restart the backend before every take, each flag fires once per start. Full flags and rig setup are in the repo README.
